# 🏦 Investors Portfolio Bot

Telegram-бот для отслеживания криптовалютных портфелей инвесторов с аналитикой,
регулярными отчетами и алертами волатильности.

## Возможности

- ⌨️ **Reply-навигация** — управление кнопками под полем ввода (ReplyKeyboardMarkup), без inline.
- 🧩 **Rich Messages (Bot API 10.1)** — портфели, P&L и аналитика выводятся прямо в чат
  нативными таблицами (`<table>`), заголовками и блоками цитат — без Web Apps.
- 👥 **Инвесторы** — ведение портфелей по сделкам: каждая покупка фиксируется как
  **точка входа** (цена, количество, дата). Если дата не указана — бот определяет её
  автоматически по цене через исторический график CoinGecko.
- 💰 **Продажа актива** — фиксация продажи (цена, количество, дата) с расчётом P&L сделки;
  контроль остатка, чтобы нельзя было продать больше, чем есть.
- 💹 **Прибыль/Убыток** — отдельный раздел: сводная таблица P&L по всем инвесторам, а по
  выбору инвестора — детализация по каждому активу (средняя цена входа, реализованный и
  нереализованный P&L, % роста/падения).
- 📊 **Аналитика** — топ роста и падения за 24ч по монетам из портфелей, общий отчёт.
- ⚙️ **Настройки** — частота отчётов, порог алертов (по умолчанию ±30%), управление админами,
  назначение чата для отчётов прямо из меню.
- 🗞 **Фоновые задачи** — регулярный сводный отчёт и проверка волатильности каждые 15 минут
  с алертами в аналитический чат.
- 🔒 **Безопасность** — бот полностью игнорирует всех, кто не указан в `ALLOWED_USERS`
  или не добавлен админом через меню.

### Модель данных

Активы хранятся не как «текущее количество», а как журнал **сделок** (таблица `transactions`:
покупки и продажи). Текущий остаток = сумма покупок − сумма продаж, средняя цена входа и P&L
считаются на лету. Данные из старой схемы `portfolios` мигрируют автоматически при первом
запуске (как покупки с неизвестной ценой входа — P&L по ним помечается «н/д»).

## Технологии

Python 3.10+, aiogram 3.x, aiosqlite, aiohttp, APScheduler, CoinGecko API.

> **Требуется Bot API 10.1+** (июнь 2026) — для нативных таблиц через метод
> `sendRichMessage`. aiogram 3.28 вышел до этого обновления, поэтому метод
> вызывается напрямую сырым HTTP-запросом (см. `app/services/rich.py`).
> Официальный сервер `api.telegram.org` поддерживает его автоматически.

## Установка и запуск

```bash
# 1. Клонировать репозиторий и перейти в него
git clone <repo-url> && cd investorsportfels

# 2. Создать виртуальное окружение и установить зависимости
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 3. Создать конфигурацию
cp .env.example .env
# Отредактировать .env: вписать BOT_TOKEN, COINGECKO_API_KEY, ALLOWED_USERS

# 4. Запустить бота
python main.py
```

База данных SQLite (`portfolio.db`) создается автоматически при первом запуске.

## Структура проекта

```
├── main.py                  # точка входа: инициализация и запуск
├── requirements.txt
├── .env.example             # шаблон конфигурации (сам .env не коммитится!)
└── app/
    ├── config.py            # загрузка настроек из .env
    ├── states.py            # FSM-состояния навигации (экраны и шаги ввода)
    ├── utils.py             # парсинг чисел и дат
    ├── database/db.py       # асинхронный слой SQLite (сделки + P&L)
    ├── services/
    │   ├── coingecko.py     # клиент CoinGecko (кэш цен + поиск даты по цене)
    │   ├── reports.py       # карточки портфелей и аналитика (rich-таблицы)
    │   ├── pnl.py           # расчёт прибыли/убытка и таблицы P&L
    │   └── rich.py          # отправка Rich Messages (Bot API 10.1)
    ├── middlewares/access.py# контроль доступа по белому списку ID
    ├── keyboards/reply.py   # reply-клавиатуры (кнопки под полем ввода)
    ├── handlers/            # старт, инвесторы, аналитика, P&L, настройки
    └── scheduler/tasks.py   # фоновые задачи APScheduler
```

## Важно про чат для отчетов

Если `ANALYTICS_CHAT_ID` не задан в `.env`, добавьте бота в нужный чат
(или откройте личный диалог), вызовите `/start` → «⚙️ Настройки» →
«📍 Отчеты в этот чат» — ID сохранится в базе.

## Безопасность

- Никогда не коммитьте `.env` — он в `.gitignore`.
- Если токен бота попал в переписку/публичный доступ — перевыпустите его у @BotFather.
